# Doc Editor 注释来源

## 编辑行为

Doc Editor 展示「源码注释」和只读的「补充说明」。源码列显示当前声明的注释正文。方法参数和 record 组件读取所属声明的同名 `@param`，普通注释只有能定位到唯一且可写的原注释时才就地修改。缺少正文时显示「未写注释」，编辑框从空白开始，可写声明支持手动新增或用 AI 生成。依赖源码和从 Proto getter 生成说明的条目可用于 Markdown 草稿。

补充说明保留来源标签，涵盖 OpenAPI、Validation、Spring 默认值、枚举引用、依赖源码及生成的字段说明。例如，带有 `@Min(3)` 的字段在补充列显示「[校验约束] 最小值:3;」。如果字段仅有这一条约束，源码列仍显示「未写注释」。

「必填」只读展示原有解析结果，并作为 Markdown 导出的取值。补充说明解析 `ValidationConstant` 中的 Jakarta 和 Javax 标准约束，包括边界、符号、格式、时间和空值规则。`@NotNull`、`@NotBlank`、`@NotEmpty` 的具体规则显示在补充说明，其余约束随既有描述优先级参与文档输出。`@Valid` 表示级联校验。

## 数据与回写

提取器将源码正文和有序补充片段放入描述模型。模型随接口描述、参数、请求头和请求与响应的 Body 树传递，缓存复制和文档行转换保留来源。预览、Markdown、YApi 和 Postman 用 `getDesc()` 读取完整描述，按现有优先级合成。例如，`@Schema(description = ...)` 继续优先用于发布文档，源码列仍展示字段的 JavaDoc 正文。

手改、逐行生成和整类生成通过同一服务读取源码，保存时校验源文件版本。打开单元格时使用最新正文，原样提交多行注释时跳过写入。已有普通注释可就地更新，已有 JavaDoc 保留 `@see` 等块标签和内联引用，引用展开内容始终来自解析。保存后重新提取描述并刷新同一声明对应的表格行。

复制 Markdown 可使用正在编辑的临时正文合成该次导出的描述，补充片段继续独立存在。选择复制时跳过源码写入。

## 验收

- 实际注释与补充说明同时存在，手动编辑只提交正文，补充列保持只读。
- 仅有校验约束时从空白新增注释，保存后的源码中只出现新正文。
- OpenAPI 覆盖正常导出，临时 Markdown 草稿可替换本次复制的基础描述。
- 枚举补充说明在缓存复制和表格转换后仍可追踪，JavaDoc 回写保留原引用。
- 普通注释可就地改写，Proto getter 文档生成条目不可作为源码写入目标。
- 新的单元格编辑从最新文本开始，编辑期间遇到外部修改时拒绝写入，原样提交多行注释保持原文。
