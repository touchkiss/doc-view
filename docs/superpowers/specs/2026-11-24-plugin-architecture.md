# Doc View 架构重构设计

交付物仍为一个 IntelliJ 插件和一个安装包。此次用户可见的变化集中在操作入口。接口识别、生成结果、源码写回、已有项目配置和快捷键都属于兼容范围。基线提交为 `3a48b46c`，其离线测试记录为 468 项通过，打包任务成功。

## 菜单与操作目标

编辑器、项目树的右键菜单末尾各注册一个「Doc View」子菜单。菜单内按预览文档、编辑文档、复制为、导出、上传到、源码注释排序，按目标显示可执行项，空分组隐藏。工具窗口目录已有明确上下文，直接列出适用操作，保留打开源码、刷新、展开和清空等目录专属操作。工具菜单保留项目级术语分析，IDE Generate 菜单保留批量生成入口，HTTP Client 的原生运行和复制命令保留原位置。

| 触发位置 | 目标及交互 |
| --- | --- |
| 编辑器 | 以当前编辑器的文件、光标声明和选区为准。已有选区时，注释快捷键及其菜单项显示并执行「翻译选区」，无选区时按声明显示「生成注释」。 |
| 项目树 | 以右键选中的文件或目录为准。支持解析的单文件可预览，Java 源码目录按既有支持范围提供批量或包注释操作。多选仅展示支持整个选集的命令。 |
| 工具窗口与预览工具栏 | 目录操作以所选节点为准，预览操作以当前文档为准。单项和批量的命名分别写明对象与范围，上传分组使用平台名称。 |

编辑器、目录树和工具栏分别负责取目标。同一操作共享适用条件与执行逻辑，执行时重新检查目标是否有效。菜单刷新仅判断资格，耗时的解析与网络请求在触发后运行。原有 action ID 及其 Keymap 映射保留。项目树选择 A、编辑器正在显示 B 时，对 A 的操作始终作用于 A。

## 功能边界与依赖

| 功能 | 职责及依赖方向 |
| --- | --- |
| 源码解析 | 从 PSI 提取接口、类型、字段和注释元数据。保留合成 Proto 类、Feign、Dubbo、Spring、record、POJO 及普通接口配置的路由顺序。将框架路由从 DocViewService 的文档构建职责中提取。缓存跟随项目与源码变更生命周期。 |
| 文档输出 | 从文档数据及显式传入的生成设置构造模板变量，渲染 Markdown、JSON、JSON5 与请求示例。逐步从 DocViewData 提取构造和渲染逻辑，兼容已有 Velocity 变量、Jackson 字段投影和用户模板。单项与项目导出复用同一渲染路径。 |
| 预览与编辑 | PreviewForm 保留组件组合，拆出后台加载与渲染的取消、结果发布和预览组件释放。过期结果不得覆盖新选择。Doc Editor 分别处理草稿变更和显式源码写回，校验及补充说明保持只读。 |
| 源码注释 | Java、Kotlin、Proto 各自处理声明识别与写回，复用已有模板、词典、翻译、AI 术语服务。保持单项、多光标、批量、包注释和已有注释处理策略。网络请求与 PSI 写操作分开，写回前重新定位目标。 |
| 平台上传与 MCP | 编辑器、预览、目录和 MCP 调用相应上传用例。平台实现各自负责文档映射、配置、传输及错误解释。MCP 保持现有工具名、参数、响应和授权边界。 |
| IDE 与可选插件 | 插件描述、Action、持久化组件和工具窗口负责接入 IDE。Kotlin、Proto、HTTP Client 的专属实现留在相应可选边界内，基础插件加载路径避免引用缺席的插件类型。HTTP Client 保留 JSON5 编辑、单条和批量运行及复制 cURL。 |

已有类按真实调用者逐步迁移。涉及持久化的组件保留状态名、存储文件和字段兼容，涉及模板和 MCP 的数据结构保留外部契约。提取共享代码前对照调用路径，尤其检查索引状态、线程要求、取消、错误通知及项目关闭后的资源释放。

## 迁移与验收

1. 先统一菜单注册、目标识别和命令命名。验证右键与快捷键、不同语言、目录、多选、无关文件及工具窗口选中节点，检查空分组与重复入口。
2. 提取框架路由与文档渲染，按 Spring/Feign、Dubbo、POJO/record、Proto 逐条迁移调用者。使用现有路由、Jackson、校验、模板、请求及导出回归用例比较结果。
3. 拆分预览任务与组件生命周期，贯通字段编辑和注释写回。验证快速切换、取消、项目关闭、预览降级、撤销及只读元数据。
4. 收拢上传入口与可选插件接入，验证三个平台的传输契约、MCP 响应、原有配置加载及依赖缺席场景。测试使用本地替身。
5. 各阶段运行受影响测试，集成后执行完整测试、插件打包与本地 IDE 兼容检查。在沙箱 IDEA 手动验收实际菜单位置、快捷键、编辑与预览。单列无法执行的环境组合及人工验收项。

完成条件为各功能通过原入口或已约定的新菜单入口可达，旧配置及模板可加载，关键输出与写回行为通过回归验证，菜单在不同上下文正确选择目标。按这些条件验收每次迁移，避免仅凭文件移动或行数减少判断完成。

## 实现导航

| 修改场景 | 从哪里开始 |
| --- | --- |
| 增加右键命令或调整可见性 | 在 `plugin.xml` 注册，沿 `ActionSelection → AbstractAction → DocumentTarget` 获取操作对象。文件级批量命令使用原始选择，类级命令解析声明。 |
| 修改生成结果 | `DocViewServiceResolver` 决定解析器，`ParamPsiUtils` 构建字段树，`DtoPropertyTypes` 处理泛型与元素类型，`PsiJsonExamples` 生成类型示例。 |
| 调整导出与预览格式 | `DocumentMarkdownRenderer` 选择工程模板，`DocViewData` 提供模板属性，`TemplateParameterMapper`、`MarkdownTables`、`Json5ExampleRenderer` 负责各自的输出。 |
| 修改预览或 Doc Editor | `PreviewRequests` 管理并发读取、取消和发布，`MarkdownPreviewPane` 管理原生预览和降级，`DocEditorFields` 管理字段映射和编辑草稿。 |
| 修改源码注释 | `SourceDescriptionService` 定位目标并校验写回时的版本，`SourceDescriptionGenerator` 准备候选说明，`JavaDescriptionText` 负责 Javadoc 正文、参数标签和内联引用的重写。 |
| 修改平台集成 | `DocViewUploadService` 调度 IDE 上传，`UploadPlatformPopup` 统一平台选择。`integration/YApiUploadOrchestrator` 供 IDE 和 MCP 复用，`McpServerService` 管理启停，`SdkMcpTransport` 处理 HTTP 与 JSON-RPC。 |
