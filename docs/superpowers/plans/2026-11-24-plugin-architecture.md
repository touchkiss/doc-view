# Doc View 架构迁移实施计划

目标是保留现有插件的全部能力、配置、快捷键与输出契约，统一 IDE 菜单操作。使用现有 Java、IntelliJ Platform、Swing、Gradle 构建体系。

1. 检查 plugin.xml 的 Action ID、菜单引用、快捷键和可选描述符；统一编辑器与项目树入口、选择目标及动作命名，复核工具窗口同类操作。
2. 从 DocViewService 分离解析路由，从 DocViewData 分离模板数据与渲染职责；通过现有解析和文档输出测试验证。
3. 拆分 PreviewForm 的后台工作及资源生命周期，复核 Doc Editor 的草稿和写回路径；运行 UI 及取消回归。
4. 拆分 SourceDescriptionService 中的注释生成、文本重写；隔离 McpServerService 的 HTTP 传输与应用服务生命周期；核对三方集成与可选功能入口。
5. 对照重构前的全部 Action ID、快捷键和可选描述符；运行完整测试、安装包构建、IDE 兼容检查。分别记录自动和交互验收结果。

## 验收记录

- 重构前常规套件为 468 项。最终常规套件为 477 项，另有 1 项可选插件禁用测试，均通过。
- 对比新旧安装包内的四个插件描述符，原有 39 个命令、11 个分组、13 条快捷键声明和原有服务、设置页、可选依赖注册均保留。
- IDEA 263.7307.200 独立沙箱中，验证了项目树与编辑器选中不同文件时的预览目标、右键层级、选区翻译的菜单切换及索引期间隐藏空组。线上文档平台写入与真实模型翻译未执行。
- 同一 IDE 和 Proto 依赖下，Plugin Verifier 对最终安装包报告 25 处弃用 API、11 处内部 API、3 处计划移除 API、31 处实验 API 以及 1 项 Kotlin 兼容性声明警告。基线中的 1 处 override-only 违规已消除，弃用 API 从 32 处降至 25 处。仓库将内部和弃用 API 列为失败条件，严格门禁仍未通过。
